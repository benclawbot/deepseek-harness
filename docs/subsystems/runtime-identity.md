# Runtime identity

English | [中文](runtime-identity.zh.md)

The **runtime-identity** subsystem is
[`packages/core/runtime-identity`](../../packages/core/runtime-identity/) —
the merge-extensible provider contract, the `ctx.runtime` registry, the
`runtime/world-state` prompt section, and the heartbeat event emitter.
The package ships the Service Definition and the Consumer (the prompt
section); every shipped profile ships a Service Provider (a
`RuntimeIdentityProvider`).

## The seam

A capability seam has three roles. Runtime identity is no exception.

- **Service Definition** (`packages/core/runtime-identity`): the
  `RuntimeIdentityRegistry` Cordis `Service` plus the merge-extensible
  `RuntimeIdentity`, `RuntimeCapabilities`, and `RuntimeIdentityProvider`
  types. The registry owns the canonical, host-fiber-scoped identity;
  consumers read the latest snapshot through `current()`.
- **Service Provider** (every shipped profile): each profile's bundle
  implements `RuntimeIdentityProvider` and registers it against
  `ctx.runtime` in its `apply()`. The Web profile is the first concrete
  example ([`packages/bundle/web-app/src/index.ts`](../../packages/bundle/web-app/src/index.ts));
  headless, sdk, sdk-minimal, acp, and the desktop host follow the same
  pattern.
- **Consumer** (`packages/core/runtime-identity/section`): the
  `runtime/world-state` prompt section registered once by this package.
  Its text derives from `ctx.runtime.current()` at every assembly, so
  every turn the model sees the running profile's identity.

The seam is mandatory. `verify-application-entrypoints` rejects any
profile that does not transitively depend on a package that registers
a provider.

## Provider contract

```ts ignore-check
export interface RuntimeIdentityProvider {
  /** Seed or refresh the canonical identity. */
  snapshot(): RuntimeIdentity
  /** Begin emitting `runtime/heartbeat` at `intervalMs`; return a disposer. */
  startHeartbeat(intervalMs: number): () => void
  /** Optional hook the registry calls on `invalidate()`. */
  onInvalidate?(reason: RuntimeInvalidateReason): Promise<void>
}
```

`snapshot()` MUST be synchronous and idempotent within one provider
instance; the registry caches the result and replays it across the host
fiber without recomputation. The returned object MUST be
JSON-serializable (the `runtime/identity` event payload is persisted
verbatim).

`startHeartbeat(intervalMs)` MUST return a disposer that stops the
underlying timer; the registry installs it as a Cordis effect so
provider unload tears it down without leaks.

The default heartbeat interval is 5000 ms; the floor is 100 ms.
Profile-specific configurations may override through `ctx.config` reads
inside `apply()`.

## Public surface

```ts ignore-check
declare module '@deepseek-ai/cordis' {
  interface Context {
    runtime: RuntimeIdentityRegistry
  }
}
```

`ctx.runtime.register(key, provider)` returns a disposer. Duplicate keys
throw. `ctx.runtime.current()` returns the latest committed identity
or `null` when no provider is registered. `ctx.runtime.invalidate(reason)`
re-snapshots the active provider and commits the new identity to the
session log.

## Session events

```ts ignore-check
declare module '@deepseek-ai/dsh-session/types' {
  interface SessionEventMap {
    'runtime/identity':       RuntimeIdentityEvent
    'runtime/heartbeat':      { seq: number; ts: number }
    'runtime/heartbeat-lost': { lastSeq: number; gapMs: number }
  }
}
```

The three events are first-party; the persistence read path treats them
as required-on-read in the same vocabulary as every other
repository-owned event. The
[`KNOWN_SESSION_EVENT_TYPES`](../../packages/core/session/src/known-event-types.ts)
set is regenerated by `scripts/gen-persistence-catalog.ts` and includes
them automatically.

## Prompt section

`runtime/world-state` is registered once by this package's `apply()`.
Its text derives from `ctx.runtime.current()` at every assembly; the
section order is allocated through `getSectionOrder('RUNTIME_WORLD_STATE')`
at 10100, the slot the Web profile's retiring `WEB_SURFACE` section
occupied. The section name is profile-generic; per-profile differences
(present or absent `canonicalUrl`, present or absent `sourceRoot`)
appear in the rendered text rather than the section name.

```text
You are running inside the DeepSeek Harness.
Profile: web
Canonical URL: http://127.0.0.1:3080
Build fingerprint: sha256:abc
Source checkout: /Users/me/deepseek-harness
Capabilities: network, filesystem, shell, sandbox
Process id: 1234
```

`headless` and `acp`'s stdio transport render no `Canonical URL`;
`desktop` renders its `dsh-app://` scheme instead of a loopback URL.
The capability list is in a fixed order (`network`, `filesystem`,
`shell`, `sandbox`) so the section text is deterministic across hosts.

## Invariant companion

`./invariant` (`name = 'runtime-identity-invariant'`,
`inject = ['invariants']`) installs three relational checks against the
session log:

1. `runtime/heartbeat.seq` is strictly monotonic per session log.
2. `runtime/heartbeat-lost.lastSeq` matches the most recently committed
   heartbeat seq for the session.
3. Two `runtime/identity` events with the same `buildFingerprint` are
   refused (a profile switch must change the fingerprint).

Load the companion beside `@deepseek-ai/dsh-invariants` to enable the
checks.
